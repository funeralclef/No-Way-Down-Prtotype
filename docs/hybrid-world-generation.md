# Hybrid world generation

`HybridV1` moves one complete production chapter to authored content without changing the public arena, progress or streaming APIs.

## Responsibility split

| Component | Owns | Does not own |
| --- | --- | --- |
| `HybridWorldPlanner` | seed, pipeline version, weighted definition choice, neighbour and socket compatibility, recipe fingerprint | scene nodes, transforms, encounter state |
| `HybridWorldAssembler` | PackedScene instancing, `Entry` alignment, `Exit` hand-off, seeded obstacle-slot decoration, assembly fingerprint | generation-ahead policy, arena completion, pruning |
| `WorldSectionRuntime` | one run's title, bounds, arena state, route style, root and content identity | immutable catalog metadata |
| `WorldSectionStream` | section lookup and retain-behind release | topology and visual construction |
| `ProceduralWorld` | orchestration, generation cursor, arena/progress facade and transition between legacy and authored recipes | model-internal node paths |

## Production sequence

The production `main.tscn` assigns `reference_catalog.tres` and selects `HybridV1`.

Initialization validates the selected recipe transactionally under a temporary in-tree owner and releases it immediately. A broken scene, obstacle contract or socket therefore disables the hybrid path before any persistent slice section is added.

1. The first chapter is generated by the legacy pipeline and provides the control baseline.
2. After arena one, the planner's four-entry recipe creates `reference_travel` → `reference_connector` → `reference_arena` → `reference_exit_connector`.
3. The exit socket returns to `Standard`, so the legacy continuation can begin at the same generation cursor.
4. Authored and legacy records enter the same `WorldSectionStream`; generation-ahead and retain-behind do not branch by content source.

The slice targets arena two by default. This can be moved with `HybridSliceArenaOrdinal`, but changing production order requires updating the pinned integration expectations.

## Determinism

The pipeline exposes version `1`, a plan fingerprint and a runtime assembly fingerprint. Chunk and obstacle selection use local `RandomNumberGenerator` instances derived from the explicit generation seed. They do not consume random values for geometry placement from the global legacy stream.

Changing the kind sequence, compatibility rules, seed derivation or weighted-choice order requires a new pipeline version. Catalog candidates are sorted by `ContentId` before weighted selection so resource-array reordering alone does not silently change the result.

## Safe extension

Add new scenes through the world-content contract and catalog. The planner may select them without a `ProceduralWorld.cs` change when their kind, socket profiles, neighbour masks, chapter, difficulty and weights fit the recipe. Obstacles additionally filter on chunk kind, theme, slot footprint and required gameplay tags.

Do not remove the corresponding legacy builder until representative final content passes the hybrid integration probe, visual review and a measured production run. Pass 6 owns that category-by-category cleanup.

## Verification

- `hybrid_world_assembler_probe.tscn`: planner determinism, old/new comparison, seams, section ranges, route width, reachable spawn markers, obstacle slots and streaming lifetime.
- `hybrid_world_visual_review.tscn`: actual assembler output for the four authored chunks.
- `world_content_contract_probe.tscn`: immutable definition and replaceable-scene contract.
- `world_generation_settings_probe.tscn`, `run_arc_probe.tscn`, `traversal_setpiece_probe.tscn`, `arena_reward_integration_probe.tscn`, `run_finale_integration_probe.tscn`: legacy and public gameplay regressions.
